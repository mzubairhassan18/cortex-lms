GRAPH VIEW — IMPLEMENTATION NOTES (read before touching graph.js)
------------------------------------------------------------------
2026-10-03  Files: public/js/graph.js + public/graph.css. Entry: initGraph()
            is the FIRST call in main.js init(). Hooks: state.view,
            state.onGraphChange (set on enter, cleared on exit).
- Node elements are keyed and REUSED across renders; re-render = position and
  class writes only. NEVER replace a node's innerHTML — it holds live DOM.
- `moved` is a LIFO journal [{el, parent, next, display}]; restore pops it in
  reverse so the app is byte-identical after leaving the graph view.
- NO MODULE MAY IMPORT graph.js (cycle). To tell the graph something changed,
  call state.onGraphChange() (conversations.js, explain-ui.js already do).
- Overlay sync: a MutationObserver mirrors #summary-overlay / #settings-overlay
  / #library-overlay `class` -> summary becomes a node, and the sidebar opens
  ONLY while an overlay that lives inside it (settings/library) is showing.
- Delegated explain handlers live in interactions.js as named functions behind
  attachExplainHandlers(host); graph mode registers them on #graph-nodes too.
- Fixed node sizes (DIM) keep layout a pure function — no measure pass. If a
  node's content ever needs to drive its size, that assumption breaks.
- Test data discipline: manual UI tests created 2 explanations and one
  "New conversation"; both were removed before the P1.1–P1.13 commit.
  Baseline data = 6 conversations, 10 messages on the active one, 0 explains.
